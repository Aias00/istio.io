Istio に新しいドキュメントを貢献するには、次の手順を実行してください：

1. 対象読者と情報の想定用途を特定します。
1. 貢献したい[コンテンツタイプ](#content-types)を選択します。
1. [タイトルを決める](#choosing-a-title)。
1. [ドキュメント貢献ガイド](/ja/about/contribute)に従って執筆します。
1. [GitHub リポジトリ](https://github.com/istio/istio.io)に貢献を提出します。
1. [レビュー プロセス](/ja/about/contribute/review)を経て、貢献がマージされるまで進めます。

## 対象読者と情報の想定用途を特定する {#identify-the-audience-and-intended-use}

良いドキュメントは、読者の目的、知識レベル、情報の活用方法を理解することから始まります。これがなければ、提供すべき情報の範囲や深さ、理想的な構成、必要な補足情報を決めることができません。以下は実践例です：

- 読者が特定のタスクを実行する必要がある場合：どのタスクを実行すべきかを明確にし、番号付きの手順で詳細を示します。単なる概要説明ではなく、具体的な手順を提供します。
- 読者がタスクを実行する前に概念を理解する必要がある場合：前提条件を説明し、その情報へのリンクを提供します。
- 読者が意思決定を行う必要がある場合：決定のタイミング、選択肢、選択基準など、必要な概念情報を提供します。
- 読者が運用担当者であり、ソフトウェアエンジニア（SWE）でない場合：スクリプトを提供し、開発者向けのコード例リンクは避けます。
- 読者が製品の機能拡張を必要とする場合：拡張方法の例を示し、簡単なシナリオで説明します。
- 読者が複雑な機能の関係を理解する必要がある場合：大量の文章ではなく、関係を示す図を提供します。

最も重要でよくある間違いは、読者が必要とする情報が分からないために、持っているすべての情報を単に提供してしまうことです。

特定のコンテンツの対象読者について支援が必要な場合は、[ドキュメントワーキンググループ](https://github.com/istio/community/blob/master/WORKING-GROUPS.md#istio-working-groups)の隔週ミーティングでご相談いただけます。

## コンテンツタイプ {#content-types}

対象読者と情報の用途が明確になったら、最適なコンテンツタイプを選択します。下表は、サポートされているコンテンツタイプ、想定読者、各タイプの目的を示しています：

      <td>プロジェクトの基本知識を持ち、機能の仕組みを知りたい読者。</td>
    </tr>
    <tr>

        <li>Istio 機能の紹介。</li>
        <li>Istio でタスクやユースケースを実現する方法の詳細。タスクや例と異なり、ブログ記事は公開後に技術的な保守やテストは行いません。</li>

      <td>ニュース項目</td>
      <td>

      </td>

    </tr>
    <tr>
      <td>FAQ</td>

## タイトルを決める {#choosing-a-title}

検索エンジンで見つけてもらいたいキーワードを含むタイトルを選びましょう。Istio のすべてのコンテンツファイルは `index.md` という名前ですが、各ファイルはタイトルのキーワードを使ったディレクトリに格納され、単語はハイフンで区切り、小文字にします。ディレクトリ名はできるだけ短くし、クロスリファレンスの作成や保守を容易にします。

## GitHub への貢献提出 {#submit-your-contribution-to-GitHub}

GitHub に不慣れな場合は、[GitHub を使ったコミュニティ参加](/ja/about/contribute/github)を参照し、ドキュメント変更の提出方法を確認してください。

公開方法やタイミングの詳細は、[ブランチ戦略](/ja/about/contribute/github#branching-strategy)をご覧ください。ここでは、ブランチや `cherry picking` を使った公開方法を説明しています。
