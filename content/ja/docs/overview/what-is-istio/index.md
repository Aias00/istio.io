Istio は、既存の分散アプリケーションに透過的にレイヤー化できるオープンソースのサービスメッシュです。
Istio の強力な機能により、サービスの保護、接続、監視を統一的かつ効率的に実現できます。
Istio は、サービスコードをほとんど変更せずに、負荷分散、サービス間認証、監視を実現する手段です。主な特徴は次のとおりです：

- 双方向 TLS 暗号化、強力な ID ベースの認証・認可によるクラスタ内サービス間通信の保護
- HTTP、gRPC、WebSocket、TCP トラフィックの自動負荷分散
- 豊富なルーティングルール、リトライ、フェイルオーバー、フォールトインジェクションによるトラフィック制御
- アクセス制御、レート制限、クォータをサポートするプラグイン可能なポリシーレイヤーと設定 API
- クラスタ内すべてのトラフィック（入口・出口含む）の自動メトリクス、ログ、トレース

Istio はスケーラビリティを重視して設計されており、さまざまなデプロイ要件に対応できます。Istio の{{< gloss "control plane" >}}コントロールプレーン{{< /gloss >}}は Kubernetes 上で動作し、
クラスタ内のアプリケーションをメッシュに追加したり、[他クラスタへ拡張](/ja/docs/ops/deployment/deployment-models/)、
さらには[Kubernetes 外の VM や他エンドポイントと接続](/ja/docs/ops/deployment/vm-architecture/)することも可能です。

多くのコントリビューター、パートナー、インテグレーター、ディストリビューターによるエコシステムが Istio を拡張し、さまざまなシナリオに適用しています。
Istio は自分でインストールすることも、多数の[ベンダー](/ja/about/ecosystem)が提供する製品を利用して管理することもできます。

## 仕組み {#how-it-works}

Istio は、すべてのネットワークトラフィックをプロキシでインターセプトし、設定に応じてアプリケーション認識機能を提供します。

コントロールプレーンは、必要な設定やサービスのビューをもとにプロキシを動的にプログラミングし、ルールや環境の変化に応じて更新します。

データプレーンはサービス間通信を担います。サービスメッシュがなければ、ネットワークはトラフィックの内容や送信元・宛先に基づく判断ができません。

Istio は 2 種類のデータプレーンモードをサポートしています：

- **Sidecar モード**：クラスタ内の各 Pod に Envoy プロキシをデプロイ、または VM 上のサービスと並行して実行
- **Ambient モード**：各ノードに L4 プロキシを配置し、必要に応じて各ネームスペースに Envoy プロキシを追加して L7 機能を実現

[どちらのモードが適しているかはこちら](/ja/docs/overview/dataplane-modes/)をご覧ください。
